# Contributing to Zelax Robotics

Start with a specific question and enough context for another person to understand it. A useful contribution can be a small observation, a sketch, a clearer explanation or an experiment proposal.

## Choose the right place

- **Early ideas and conversation:** [Sensing and robotics at Zelax Lab](https://lab.zelax.com/c/sensing-and-robotics/8).
- **A concrete proposal or documentation problem:** [Open a GitHub issue](https://github.com/zelaxcom/zelax-robotics/issues/new/choose).
- **An improvement to an existing document:** Open a pull request explaining what changed and why.

You can participate in the Lab without learning Git. A maintainer can help turn a clear discussion into a more structured proposal.

## Make a proposal useful

Describe the object, the task and the difficulty you have noticed. Include a photo or labeled sketch where it adds information. Say whether the idea is a concept, a prototype or an observation from a test.

Use the [experiment template](docs/experiment-template.md) for a proposed test or a report of work you have done. Report unsuccessful attempts too, and distinguish measurements from estimates or expectations.

## Keep contributions focused

One issue or pull request should address one clear question. Use descriptive file names, define unfamiliar terms and link the related Lab conversation when there is one.

If you share files, include their source, version and reuse terms. Only upload material you can share publicly. Label generated illustrations as concepts when they do not document a real object or experiment.

## Review and discussion

Contributions will be considered through discussion and review. An accepted document records an idea or observation; it does not by itself establish a product specification or validated result.

For a private question about contributing, contact [lab@zelax.com](mailto:lab@zelax.com).
